# Secure Folder Bridge

GalaxyのSecure Folder内にあるファイルを、通常側と仕事用プロファイルのファイルマネージャーからフォルダとして開くrootアプリです。ファイルをコピーせず、内部ストレージの `SecureFolder` から元の共有ストレージへ接続します。

## 画面と設定

Material 3の配色と部品を使い、端末のライト・ダークテーマに合わせて表示します。上部で接続状態と読み書きモードを確認でき、通常側・仕事用それぞれのフォルダカードからパスをコピーできます。接続中は設定を固定し、エラーの詳細は別のカードに表示します。ライセンスは右上のメニューから開けます。

日本語・英語・中国語（簡体字／繁体字）・韓国語・ドイツ語・フランス語・スペイン語・ポルトガル語（ブラジル）の9言語に対応します。右上の「言語」からアプリ単位で変更でき、初期設定では端末の言語に従います。

## 使い方

1. アプリをインストールし、KernelSUでrootを許可します。
2. 端末本体とSecure Folderを解除します。
3. 「フォルダを接続」をオンにします。
4. Samsungマイファイルなどで、内部ストレージの `SecureFolder` を開きます。

「仕事用プロファイルにも表示」は初期設定でオンです。通常側（ユーザー0）と仕事用側（ユーザー10）のそれぞれの内部ストレージへ `SecureFolder` を表示します。どちらも同じSecure Folder内の元ファイルへ接続するため、編集内容は共通です。仕事用がロック・休止中ならその側だけを切断し、利用可能になったら再接続します。

各ユーザーの `SecureFolder` は複製ではなく、同じ元データへの入口です。検証端末の共有ストレージではシンボリックリンクを開けないため、普通のフォルダとして読み書きできる接続方式を使います。

初期設定は**読み書き可能**です。作成・編集・移動・削除はSecure Folder内の元ファイルへ直接反映されます。必要な場合だけ「読み取り専用」をオンにしてから接続してください。

接続中だけ通知とroot監視処理が動作します。画面消灯、端末本体またはSecure Folderのロック、制御プロセスの終了時に接続を解除します。再起動時の自動接続はしません。

## 対応範囲

- rootとグローバルmount namespaceを使えるKernelSUが必要です。
- 現在の対象は、Secure Folderがユーザー150として動くGalaxyです。
- Android 16以降向け、SDK 37でビルドします。実機でのコマンド検証はGalaxy S26 Ultra / Android 17です。Android 16の実機再検証は未実施です。
- 接続元は写真・Downloadなどの共有ストレージです。各アプリの内部データは含みません。
- ファイルマネージャー側には、そのプロファイルの共有ストレージへアクセスする権限が必要です。接続先は通常側が `/storage/emulated/0/SecureFolder`、仕事用側が `/storage/emulated/10/SecureFolder` です。
- 読み取り専用にはLinuxのdetached mount APIを使います。必要なAPIがない場合は読み書き接続へ勝手に変更せず、失敗として停止します。

接続中は、有効にした各プロファイルで共有ストレージを読めるアプリから内容が見えます。接続解除は新しいパスアクセスを閉じる処理です。他アプリが既に開いたファイルや保存したサムネイル、コピーは消去しません。アプリは認証情報、画面ロック、暗号化、元ファイルの所有権やSELinuxポリシーを変更しません。

## 動作確認

実データを使わない一時フォルダで、通常側・仕事用側からの読み書き・作成・名前変更・削除と編集内容の共有、読み取り専用時の書き込み拒否、制御プロセス終了後の切断を確認しています。ファイルマネージャーのGUI操作と実際の消灯・ロック操作は別の確認項目です。

ソース・ビルド方法・検証範囲は[開発者向け文書](docs/development.md)を参照してください。
